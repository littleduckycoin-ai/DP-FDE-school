# 用飞书学习 FDE 案例

学校迁移到飞书后，学员仍然只使用一个 `school-guide`。告诉 Agent 想学哪个案例、有什么工作问题，或希望整理哪几个案例的讨论，它会读取学校当前资料并开始。

> 使用 $school-guide，先读取学校最新规则，带我学习一个与我的工作有关的 FDE 案例。

第一次需要连接飞书时，Agent 会检查并准备工具，然后给你飞书授权入口。你完成 OAuth 授权即可；安装与命令操作由 Agent 处理。某些客户端缺少运行工具或飞书连接时，Agent 会说明具体缺口。登录成功后若仍无法读取学校文档，需要文档所有者补充访问权限。

## 思考保存在哪里

每个案例有基础资料、reflections 和正式拆解。你的思考、评价、问题、分歧和修订会进入该案例 reflections 下的署名知识文档；同一天学习同一案例复用一份文档，逐轮追加。它们会出现在文档正文中，供后来的学员和会前 Agent 阅读。

第一次保存时，Agent 会确认你的稳定学习标识、展示名、内容可见范围和本次会话持续记录授权。之后有值得沉淀的表达就可以自动追加，不必每轮再确认。你可以随时说“这段不记录”。Agent 讲解会与自己的观点分开，修订会保留原观点。

> 我的学习标识是 alice，展示名是 Alice。请把这次学习中适合分享的思考和问题逐轮保存到相应案例的 reflections，保存后给我链接。这段个人背景不记录。

保存成功时会获得实际知识文档链接。失败时 Agent 会给出准确目标和完整待提交内容，协助处理授权；不会把“写好了草稿”说成“已经保存”。自动追加在当前学习会话中执行，后台机器人需要单独部署与验收。

## 会前、会上和会后

> 请读取案例 01、04、06 中截至今天 18:00（北京时间）的全部学习记录，整理大家的问题、分歧和建议讨论顺序，保留作者与原文链接。

Agent 会按主题整理全量可读记录，显示资料范围和缺失，保留少数意见。重复追问不会当作多个人支持；没有记录不等于缺席。会上根据原文讨论，问题只有提出者明确表示解决后才会关闭。

> 请把这次会前整理保存到学校会议资料，并把 Agent 建议与我们实际确认的决定分开。

个人反思可以直接成为可引用的学习知识。正式案例拆解和跨案例模式由维护者审核后发布；未经审核的内容仍是提案。给案例事实的引用优先打开原 PDF 对应物理页，个人观点则打开作者的 reflection 文档。

## 迁移期间

学校通过公开入口路由声明当前使用 GitHub 还是飞书。正式迁移验收并切换前，现有 GitHub 学校继续使用；Agent 不会把一次讨论分别写进两个中台。飞书入口、文档权限、全文与图片、自动保存回执、会议汇总和审核流程均需实际验收后再向学员宣布切换。

学校资料无需克隆或保存在学员电脑。入口路由可继续放在 GitHub，它只告诉 Agent 到哪里连接，不存放飞书的案例正文、个人反馈或密钥。
