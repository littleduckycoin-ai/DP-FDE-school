# 从个人记录准备一场会

主持人给出会议标识、案例范围、截止时间，以及可选的应参与学习者标识。Agent先确定资料范围，再归纳内容；不会读取任何人的私人聊天或`.school/private/`。

## 生成可追溯的资料包

在仓库根目录执行，例如：

```sh
git fetch origin
python tools/school.py brief --meeting 2026-09-07-workshop --cases 01 04 06 --cutoff 2026-09-07T18:00:00+08:00 --expected alice bob
```

示例名单与日期不是实际人员或会议安排，请替换。默认从`origin/main`解析出的固定commit读取案例索引及学员记录；引用链接指向该commit。即使随后主分支更新，本次资料仍可追溯。尚未合并的PR不在其中。

可加`--since`限定归档时间。日期不含时区时按UTC日界处理，建议使用带时区的完整时间。只有窗口内的条目参与统计，窗口外的问题及其状态不会补入；要追踪历史未解决问题，省略`--since`并使用完整记录范围。

| 生成文件 | 用途 |
|---|---|
| `meetings/<meeting-id>/brief.md` | 可直接阅读的参与记录、开放问题、评价与分歧等，逐条链接来源 |
| `records.json` | 学员条目、问题状态、Agent反馈分别存放，便于继续聚类 |
| `manifest.json` | commit、案例范围、时间截止、来源文件摘要和统计口径 |

默认只读取共享`reflections/`，不读取私密笔记，不把canon里的编辑分析算成学员意见。按独立`learner_id`计人数；身份由学员自述。没有记录只说明当前范围没找到，不能视为缺席或没有学习。

## 让Agent做主题整理

对Agent说：“基于这份资料包，按问题主题整理分歧，提出会上优先讨论什么。”Agent另写`synthesis.md`，至少包含：

- **资料口径**：引用`manifest.json`，说明案例、时间、人数和缺失资料；没有学员记录时明确说明，不编造讨论。
- **主题清单**：每个主题概括实际问题，给出记录编号和原记录链接，注明涉及多少位独立学习者。
- **分歧与少数意见**：并列不同解释及其证据，不把相近措辞或重复提问当成共识。
- **建议议程**：按对需求判断、方案或交付的影响排序，说明理由和需要补的证据。标注这是Agent建议。

如需含尚未合并的PR，主持人必须明确指定；Agent另列来源分支与commit、PR状态，不把它混写为主分支记录。只想看自己的未提交练习可用`--working-tree`，产物会标明范围是当前工作区，不能称为全组反馈。

## 刷新与会后产物

刷新同一个会议加`--refresh`。工具只覆盖`brief.md`、`records.json`、`manifest.json`三个生成文件，保留`synthesis.md`和`decisions.md`。刷新后Agent应核对主题整理是否仍对应新的资料版本，必要时更新并说明变化。

会上明确确认的结论使用[会议决定模板](../templates/meeting-decisions.md)写到`decisions.md`，保留确认者、依据和未解决分歧。负责人、截止日期必须来自明确约定；没有约定就写“待确定”。每个人的问题状态仍由本人确认更新。

会前资料与会后决定可按授权提交为PR，方便下一轮学习引用。提炼通用结论时，再单独进入canon或patterns的审核流程。
