# 会前直接读大家的线上记录

主持人可以对Agent说：

> 请实时读取学校线上案例01、04、06的学习记录及评论，按主题整理开放问题、分歧和建议讨论顺序，保留作者与原记录链接。

需要限定范围时再补充截止时间（含时区）和应参与学习者标识。Agent先在线取资料，再做整理，不要求主持人下载仓库或运行汇总脚本。

## 资料范围

实时读取学校学习记录Issues及全部相关评论，也读取指定案例`reflections/`中已归档的记录。处理分页；原始帖子和归档条目按稳定ID或来源链接去重。未经审核的学员表达可以参与讨论，但不能当成已审教材。

记录本次抓取时间、教材commit、Issue/评论ID和更新时间。对话默认展示当前资料；如果用户指定历史截止时间，后来编辑过且无法恢复旧版的内容必须标记或排除，不能假装拿到了历史快照。

## 汇总给人看什么

- 资料口径：案例、截止时间、实际读取范围、独立学习者数量及已知缺失。
- 主题问题：每个主题保留作者、条目ID和线上链接，说明涉及哪些人。
- 分歧：并列不同解释、证据和少数意见，不能把提问次数当成支持票。
- 建议议程：按对需求判断、方案与交付的影响排序，说明理由和所缺证据；标注为Agent建议。

没有名单不推断谁没交，没有记录不等于缺席。问题只有提出者明确确认已解决才退出开放问题清单；Issue关闭本身不代表问题解决。

## 会后怎样留下来

先在对话中给出汇总。主持人要求保存并具备线上写权限时，通过GitHub在线提交到`meetings/<meeting-id>/`：`brief.md`为资料整理，`manifest.json`记录来源与时间，`synthesis.md`明确标Agent分析，`decisions.md`只写真实确认的决定。

刷新应在线重读来源，并保留此前确认的决定。负责人、截止日期和共识必须来自实际约定；没有约定就写待确定。进一步形成canon或patterns时走教材审核流程。

旧版`tools/school.py brief`仅汇总文件归档，不包含尚未归档的实时讨论，不能用于声称已经汇总全校最新反馈。
